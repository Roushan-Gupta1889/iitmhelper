# IITM Helper - Convert PWA to TWA (Google Play Store Guide)

This guide takes you step-by-step through generating an Android App Bundle (.aab) using `bubblewrap`, verifying your app, and passing Play Store reviews successfully.

---

## Part 1: Generating the Android App with Bubblewrap

### Step 1: Install Bubblewrap CLI
Open your terminal and install Bubblewrap globally using Node.js:
```bash
npm install -g @bubblewrap/cli
```

### Step 2: Initialize the Android Project
Create an empty directory for your android project, navigate into it, and initialize Bubblewrap against your live web app manifest:
```bash
mkdir iitmhelper-android
cd iitmhelper-android
bubblewrap init --manifest https://iitmhelper.online/manifest.json
```

**During initialization, Bubblewrap will ask you some questions:**
*   **Web application URL:** `https://iitmhelper.online/`
*   **Application name:** `IITM Helper` (Press Enter to accept defaults usually)
*   **Application ID (Package Name):** `com.allgenztool.iitmhelper` (Make sure it matches this exactly)
*   **Key Store location / Passwords:** Bubblewrap will help you generate a keystore file to sign your app. **WRITE DOWN THE ALIAS AND PASSWORDS YOU USE HERE.** You need them to push updates later.

### Step 3: Extract the SHA256 Fingerprint
Play Store and TWA require a mathematical proof that the website and the app are owned by the same entity. This is your SHA256 fingerprint.

Once the project is initialized, run this command to see the fingerprint generated by your keystore:
```bash
bubblewrap fingerprint android.keystore
```
**Important Action:** Copy the `SHA-256` value outputted by this command.

### Step 4: Update Your Web Server
Go back to your web codebase. Open the `.well-known/assetlinks.json` file that I've just created in the root of your project.

Replace `"PUT_YOUR_SHA256_FINGERPRINT_HERE"` with the long SHA-256 string you copied in Step 3. 

**Push these changes live so that the file is accessible at:**
`https://iitmhelper.online/.well-known/assetlinks.json`

> [!CAUTION]
> **Wait Before Build! (VERY IMPORTANT)**
> You MUST wait until `assetlinks.json` is successfully live at the URL above before proceeding to the next step. 
> 
> If you skip this, the generated app will show the Chrome address bar, and your app will be **rejected** by the Play Store. Test the URL in an incognito window first.

### Step 5: Build the Android App
Go back to your `iitmhelper-android` directory in your terminal and build the app bundle:
```bash
bubblewrap build
```
This process will create an `app-release-bundle.aab` file—this is the file you upload to the Google Play Console!

## Part 2: Play Store Review Best Practices

A TWA is fundamentally a web page acting as an app. Google rejects apps that feel like "just a website wrapped in a browser."

1.  **Valid Asset Links (CRITICAL):**
    If the `assetlinks.json` is missing, misconfigured, or inaccessible, the app will show the Chrome address bar at the top inside the app. **Google will reject this immediately.**
    *   *Test it on a real device through USB debugging before submitting.* The address bar must not be visible.
2.  **Valid Privacy Policy URL:**
    Play Store requires a privacy policy. You must submit a working link to your web Privacy Policy (`https://iitmhelper.online/pages/privacy-policy.html`) in the "App Content" section of the Play Console.
3.  **Provide Real Value / Avoid "Empty" Apps:**
    Google rejects apps described as "webviews". Ensure your listing highlights value, such as your GPA Calculators, AI Assistant, and Community tools. Emphasize that it's an interactive utility, not a blog.
4.  **Offline Capability Check:**
    Play Store testers will turn on Airplane Mode and launch your app. If it crashes or shows the Chrome "No Internet Dinosaur", it gets rejected. 
    *   *Our Status:* Your `sw.js` is already configured to catch offline navigation and present your custom `offline.html` page, so you are good here.
5.  **Target API Requirements:**
    Bubblewrap usually handles this, but constantly ensure you are targeting the latest Android SDK version required by Google Play (currently API level 34).

## Part 3: UX Improvements for Native Feel

To make your web app feel less like a "website" and more like an "app" on Android:

1.  **Disable Text Selection & Highlight Colors:**
    Users shouldn't be able to select UI text or see blue tap-highlights. Add this to your root CSS (in `styles.css`):
    ```css
    body {
        -webkit-user-select: none;
        user-select: none;
        -webkit-tap-highlight-color: transparent;
    }
    ```
    *(Note: You'll want to re-enable `user-select: text` on text inputs and textareas!)*
2.  **Hide Unnecessary "Install App" Buttons:**
    Your PWA banner (`pwaInstallBanner` in index.html) shouldn't appear inside the Android app. TWA sets a specific referer. You can hide the banner in JS if the app is launched in standalone mode:
    ```javascript
    if (window.matchMedia('(display-mode: standalone)').matches) {
       // Running as TWA or installed PWA - hide install banners
       document.getElementById('pwaInstallBanner').style.display = 'none';
    }
    ```
3.  **Implement Pull-to-Refresh:**
    Bubblewrap handles pull-to-refresh natively if you configure it. In your `twa-manifest.json` (generated by Bubblewrap), check that `enableNotifications` and pull to refresh configurations are set how you'd like them.
4.  **Smooth Page Navigation (Optional but recommended):**
    Native apps don't have white flashes between page loads. Consider making page changes happen purely via JavaScript (Single Page App approach) in the future to significantly enhance the native feel.
